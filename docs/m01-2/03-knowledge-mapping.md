# Bản đồ Kiến thức Chi tiết: Booking Platform v0
## Mapping từ Kế hoạch Học tập M1.2 vào Codebase Thực tế

Tài liệu này liên kết trực tiếp từng khái niệm, kỹ thuật và nguyên lý giao thức trong kế hoạch 2 tuần ([M1-2.md](file:///d:/Books/notes/pure-md/ps/rm/booking-platform/docs/M1-2.md)) vào các vị trí mã nguồn cụ thể của cả 2 engine (**Native Node.js** và **NestJS**), giải thích cơ chế áp dụng, các điểm then chốt cần quan sát khi đọc code/debug, và các thử nghiệm thực tế để kiểm chứng.

| **1** | **Client-Server & Request-Response Model** | `src/native/server.ts`<br>`src/nestjs/main.ts` | Server lắng nghe trên một TCP port (`3000`/`3001`). Khi client gửi request, server xử lý và **bắt buộc** phải gọi `res.end()` (ở native) hoặc trả về giá trị (ở NestJS) để đóng stream response. | Đặt breakpoint tại `http.createServer((req, res) => ...)`: Quan sát thấy một đối tượng `IncomingMessage` đại diện cho request và `ServerResponse` đại diện cho response được khởi tạo cho mỗi kết nối HTTP. | Cố tình comment dòng `res.end()` trong một handler Native; gửi request bằng `curl` hoặc trình duyệt; quan sát client bị treo vĩnh viễn (Pending) cho đến khi timeout. |
| **2** | **HTTP/1.1 Message Structure (Request Line, Headers, Body)** | `src/native/http/request-parser.ts`<br>`src/native/server.ts` | Bóc tách trực tiếp các thành phần raw: `req.method` (Request Line), `req.url` (Target Path), `req.headers` (Key-Value Metadata), và body stream. | Soi giá trị biến `req.headers`: thấy các header chuẩn hóa về chữ thường (`lowercase`), header `host`, `user-agent`, `content-type`. | **3** | **HTTP Methods & Resource Semantics (GET, POST, PUT, PATCH, DELETE)** | `src/native/handlers/`<br>`src/nestjs/**/*.controller.ts` | Định nghĩa các hành vi chuẩn REST: GET lấy dữ liệu không đổi trạng thái; POST tạo mới resource; PUT thay thế toàn bộ resource; PATCH cập nhật từng trường; DELETE loại bỏ resource. | Đối chiếu cách Native Router map `(method, path)` bằng mảng routes thủ công với cách NestJS dùng decorator `@Get()`, `@Post()`, `@Put()`, `@Patch()`, `@Delete()`. | Gửi `GET /events` nhiều lần: dữ liệu giữ nguyên; gửi `POST /events`: số lượng event tăng lên; gửi `DELETE /events/:id`: event biến mất khỏi danh sách. |
| **4** | **Safe vs Idempotent Semantics** | `src/native/handlers/events.handler.ts`<br>`src/nestjs/events/events.service.ts` | Safe: GET không làm thay đổi server state. Idempotent: Gọi $N$ lần ($N \ge 1$) có cùng hiệu ứng phụ như gọi 1 lần: PUT ghi đè cùng dữ liệu; DELETE xóa xong thì các lần sau vẫn giữ trạng thái đã xóa; POST không idempotent vì mỗi lần gọi tạo ra một bản ghi mới với ID mới. | Quan sát hàm xử lý PUT: nhận toàn bộ object và thay thế trực tiếp vào `Map`; hàm DELETE: kiểm tra nếu tồn tại thì xóa, nếu không tồn tại vẫn xử lý an toàn mà không làm hỏng state. | Viết test case gọi `PUT /events/123` liên tiếp 5 lần cùng payload: dữ liệu sự kiện vẫn là 1 bản ghi duy nhất, không nhân bản; gọi `POST /bookings` 5 lần: tạo ra 5 booking khác nhau với 5 ID khác nhau. |
| **5** | **HTTP Status Codes Mapping (200, 201, 204, 400, 404, 405, 409, 422, 500)** | `src/shared/errors/`<br>`src/native/http/response-helper.ts`<br>`src/nestjs/common/filters/` | Ánh xạ từng kết quả nghiệp vụ thành status code quốc tế chuẩn xác thay vì luôn trả về 200 kèm `status: "error"`. | Native: `res.writeHead(statusCode, headers)`. NestJS: `@HttpCode()`, `NotFoundException`, `ConflictException`, `UnprocessableEntityException`. | Gửi 8 request mô phỏng 8 trường hợp (thành công, thiếu trường, sai ID, trùng code, method sai, JSON hỏng); kiểm tra response status header nhận được khớp 100% với đặc tả. |
| **6** | **HTTP Headers & Content Negotiation** | `src/native/http/request-parser.ts`<br>`src/native/http/response-helper.ts` | Kiểm tra header `Content-Type: application/json` ở request body. Bắt buộc thiết lập `Content-Type: application/json; charset=utf-8` ở response và trả về header `Location: /events/:id` khi tạo resource thành công (201). | Xem tab Headers trong Chrome DevTools hoặc terminal `curl -v`: kiểm tra sự hiện diện của `Location: /events/<id>` khi tạo mới event. | Gửi request POST với header `Content-Type: text/plain`; quan sát server chặn lại và trả về lỗi `415 Unsupported Media Type` hoặc `400 Bad Request`. |
| **7** | **Statelessness trong HTTP** | `src/shared/storage/in-memory-store.ts` | Mỗi HTTP request gửi lên server là một giao dịch độc lập; server không lưu giữ con trỏ phiên (session state) trên TCP socket. Dữ liệu trạng thái nằm ở Data Store (Memory Store), không nằm trên connection. | Quan sát: Hai request từ hai client khác nhau gọi đồng thời đều truy cập vào cùng một data store chung mà không phụ thuộc vào thứ tự gọi của client. | Ngắt kết nối TCP và mở kết nối TCP mới, gửi request tiếp theo: server vẫn nhận diện và xử lý chính xác dựa trên URI và ID truyền trong request. |
| **8** | **Native Node.js HTTP Server (`node:http`)** | `src/native/server.ts`<br>`src/native/main.ts` | Tự dựng HTTP listener bằng `http.createServer()`. Quản lý sự kiện `request`, `listening`, `close`, `error`. Không sử dụng bất kỳ framework nào. | Quan sát mã nguồn `server.ts`: Chỉ có khoảng 50 dòng code thuần Node.js để tiếp nhận và phân phối request đến router. | Chạy `node dist/native/main.js`, dùng lệnh `netstat -ano | findstr 3000` (Windows) để thấy port 3000 đang ở trạng thái `LISTENING`. |
| **9** | **Request Stream & Chunk-by-Chunk Body Parsing** | `src/native/http/body-parser.ts` | HTTP request body là một Readable Stream. Dữ liệu truyền qua TCP có thể bị chia thành nhiều gói (packets/chunks). Phải lắng nghe `req.on('data')` gom mảng Buffer và `req.on('end')` để ghép chuỗi hoàn chỉnh trước khi parse JSON. | Đặt breakpoint trong callback `req.on('data')`: quan sát biến `chunk` nhận về kiểu `Buffer`.
